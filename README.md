# 미니 PJT: 학습지 생성 Agent

## 무엇을 푸나
초등학생 자녀를 둔 부모가, 방문 일정에 얽매이는 학습지(구몬/빨간펜) 대신 아이 수준에 맞는 수학·영어·한문 학습지를 원할 때 자동으로 받고 채점까지 받을 수 있게 한다.

**정량적 근거 (자체 추정·실측, 외부 시장조사 아님)**
- 방문 학습지는 교사 방문·채점 대기가 정해진 요일에 묶이는 반면, 이 서비스는 요청 즉시(SERVICE.md 5번 목표: 생성+검증까지 5분 이내) 생성·채점이 끝나 부모가 개입할 일 자체가 "학습지 만들어줘" 요청 한 번으로 줄어든다
- 실측: 2026-09-17에 수학·영어 각 10세트(문제 200개)를 실제 Bedrock으로 생성→오류 교차검증→채점까지 실행해 **문제은행 대체(fallback) 없이 20/20세트 성공** — 사람이 매번 문제를 손으로 내고 채점하는 것과 달리, 한 번 만든 파이프라인이 학년·과목을 바꿔가며 반복 가능함을 실측으로 확인함

## 활용한 패턴 (Day 1~7)
- Day 1: LCEL chain — 문제 생성·오류 검증을 Pydantic 구조화 출력(`with_structured_output`)으로 받음
- Day 3: ReAct — `create_agent`로 자연어 질문(question)만 보고 학년·난이도를 스스로 추출해 도구를 호출할지, 되물을지, 거절할지 판단 (테스트 확인: 학년 누락 시 되묻기, 범위 밖 학년/과목·프롬프트 인젝션·개인정보 요청 거절)
- Day 4: 도구 다중 — 문제 생성 → 오류 교차검증 → 채점 도구를 한 흐름에서 결합
- Day 5: 가드레일 — 학년 범위·과목 입력 검증(`validate_input`), 배포 전 오류 교차검증으로 출력 필터링
- Day 5: HITL — 검증 3회 실패 시 `interrupt()`로 문제은행 대체를 부모에게 승인받음 (`POST /approve`로 즉시 승인, 30초 무응답 시 자동 진행 — 둘 다 테스트 확인)
- Day 7: Observability — LangSmith 트레이스 연동 (프로젝트 `mini-pjt2-worksheet-agent`), 문제 생성·검증 각 단계가 기록됨
- Day 7: 평가(LLM-as-Judge) — `evaluation/run_eval.py`의 `judge_answer()`가 채점과 별개의 독립 LLM 호출로 `expected_traits` 충족·`forbidden` 위반 여부를 판정 (문제 생성과 별도 호출로 검증하는 `cross_validate_problem`과 같은 패턴). 영어 확장 때 실제 회귀(채점 요청에 학년을 되묻는 문제)를 이 평가로 잡아내 수정했고, round4·round5 모두 그 수정이 반영된 상태로 통과함 (자세한 경위는 트라이앤에러 회고 참고)

## 아키텍처
```
학년 입력 → 과목(수학 1~6학년 / 영어 3~6학년) · 난이도 선택
   └─ 문제 생성 (수학: 단답형 · 영어: 4지선다 빈칸 채우기, 같은 파이프라인 재사용)
         └─ 오류 교차검증 (배포 전, 다른 AI로 전수 검증 · 영어는 오답 3개의 확실한 오답 여부까지 검증 · 실패 시 자동 교체/문제은행 대체)
               └─ 화면 풀이 채점 (정답 인정 범위·힌트 부분점 반영 / 영어는 선택한 보기 비교)
                     ├─ 점수(별) 보상 (정답=2개·힌트로 정답=1개·오답=0개, 과목 통합 운영, 구현 완료)
                     └─ 주간 리포트 (과목별 overview 요약 + 과목별 날짜별 정답률 그래프·오답 주제)
```
(자세한 요구사항·정책은 [SERVICE.md](./SERVICE.md) 참고)

## 실행 방법
```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe -m uvicorn src.api:app --reload
```
또는 Docker로 (`.env`는 이미지에 안 들어있으니 `--env-file`로 넘긴다):
```bash
docker build -t mini-pjt2 .
docker run --env-file .env -p 8813:8813 -v "$(pwd)/data:/app/data" mini-pjt2
```
- `.env`에 AWS 자격증명(`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`)이 필요하다 (Bedrock 호출용)
- `.env`에 `LANGSMITH_API_KEY`를 넣으면 LangSmith에 트레이스가 자동으로 남는다 (없어도 동작에는 문제없음)
- 확인된 예시 요청: `POST /query {"question": "3학년 수학 학습지 만들어줘"}` (학년·난이도는 문장에서 에이전트가 스스로 추출한다)
- 승인 대기 확인: `GET /pending-approvals`, 승인: `POST /approve {"thread_id": "..."}`
- 서버를 띄운 뒤 브라우저에서 `http://127.0.0.1:8000/`을 열면 아이용 풀이 화면이 뜬다 (학년 선택 → 과목·난이도 선택 → 문제 풀이 → 채점 결과, [web/](./web/), Playwright로 모바일·태블릿 폭 시각 검증 완료). 1~2학년은 과목 화면에서 "영어" 버튼이 안 보인다 (영어는 3~6학년만 지원). 상단바에 오늘 날짜·요일과 "오늘 딴 별 수"가 항상 보인다
- 문제를 채점할 때마다 별을 딴다 (힌트 없이 정답 2개·힌트로 정답 1개·오답 0개, 수학·영어 통합). 학년 선택 화면과 부모 리포트에 누적 별 수를 1·10·100·1000 단위로 나눠 단위별 전용 별 아이콘으로 보여준다 — 단위가 클수록 아이콘이 크고 반짝이며, 색도 메달 등급처럼 올라간다(1개=동색, 10개=은색, 100개=금색, 1000개=무지개색). 별 안에 그 단위 숫자도 작게 적혀 있어서 어떤 단위인지 바로 알 수 있다. "오늘 딴 별 수"는 상단바에 항상 보이는 것과 별개로, 채점을 마치면 그 결과 점수 배너 안에도 한 번 더 표시된다
- 과목은 수학·영어 중 하나만 골라도 되고 둘 다 골라도 된다. 둘 다 고르면 위쪽 탭으로 수학/영어 패널을 전환하며 풀 수 있고, 채점도 과목별로 따로 한다 — "다른 학습지 받기"는 이번에 고른 과목을 전부 다 풀어야 넘어간다
- 수학은 문제마다 힌트 보기(풀이 방향만 알려줌, 정답 비공개)와 연습장(작은 그림판 모달, 마우스/터치 낙서 가능) 버튼이 있다. 영어(4지선다 빈칸 채우기)는 보기 버튼 중 하나를 고르는 방식이라 연습장은 없고, 힌트는 정답 보기 대신 문법 규칙만 알려준다
- 그날 지원되는 과목(수학·영어) 중 하나라도 안 끝내면 다른 과목의 새 학습지도 받을 수 없다 (하루 세트 = 그날 과목별 학습지 각 1세트, 자정 지나면 초기화) — 지금 풀고 있는 학습지의 답을 전부 쓰기 전에는 "다른 학습지 받기" 자체도 막힌다
- 상단바의 "부모 화면" 버튼 → 4자리 PIN(기본값 `0000`) → 승인 대기 목록 확인(과목 표시됨) 및 즉시 승인 가능. "아이 화면으로 돌아가기"로 원래 화면 복귀
- 부모 화면 → "주간 리포트 보기"에서 상단 "조회할 주" 콤보박스(이번 주~8주 전)로 지난 주들도 볼 수 있다(`GET /report/weekly?weeks_ago=N`). 과목별 요약(overview: 사용일수·정답률·힌트 사용률·완료 학습지 수)을 먼저 보고, 그 아래 과목별 상세(날짜별 정답률 막대그래프 — 빈 날은 점선 표시, 막대 클릭 시 정확한 값 readout, "표로 보기"로 테이블 전환 / 오답 주제 목록)를 본다. 난이도 조정 칩을 누르면 다음 학습지부터 그 난이도로 바로 시작된다
- 부모 화면 → "오답노트 보기"(`GET /wrong-answers?subject=...`)에서 과목별 탭으로 전환하며 틀린 문제를 최신순으로 본다(과목당 최대 50개, 넘으면 가장 오래된 것부터 자동으로 지워짐). 문제·(영어면)보기·정답·아이가 쓴 답·태그를 카드로 보여주며, 같은 문제를 여러 번 틀리면 그때마다 새 카드로 쌓인다. 아이 화면에는 이 화면으로 가는 경로 자체가 없다

## RAGAS 평가 상태

현재 1차 범위는 RAG를 사용하지 않는다. `src/retriever.py`의
`retrieve_reference()`가 아직 빈 리스트를 반환하고, `/query`의 `contexts`도
항상 비어 있으므로 지금 RAGAS를 실행하면 검색 품질이나 답변의 근거성을
측정하는 대신 "검색된 근거가 없음"을 측정하게 된다. 따라서 현재는
`evaluation/run_eval.py`의 도구 호출 검증 및 독립 LLM 판정 평가를 공식
에이전트 평가로 사용한다.

RAG를 추가하는 단계에서만 다음 절차로 RAGAS를 실행한다.

1. `retriever.py`가 검색한 문서 조각과 출처 ID를 `contexts`에 반환하고,
      에이전트 프롬프트가 그 컨텍스트를 실제 답변에 사용하도록 연결한다.
2. 검색 질의 30~50개에 대해 `user_input`, `reference`(기대 답변),
      `reference_contexts`(정답을 뒷받침하는 문서 조각)를 별도 평가셋으로 고정한다.
3. 실제 `/query` 결과에서 `response`와 `retrieved_contexts`를 수집한 뒤
      RAGAS를 실행한다. `context_precision`·`context_recall`은 정답 근거가
      평가셋에 있을 때만 해석한다.
4. 다음 지표를 보고서에 기록한다: `context_precision`, `context_recall`,
      `faithfulness`, `answer_relevancy`. 모델 변경 전후에는 같은 평가셋과
      같은 judge 모델을 사용한다.

`ragas`가 아직 `requirements.txt`에 없는 것도 의도된 상태다. 실제 검색기가
추가될 때 RAGAS 버전을 고정하고, 그때 `evaluation/run_ragas.py`와 결과
리포트를 함께 추가한다. 그 전에는 RAGAS 점수를 임의의 숫자로 채우지 않는다.

- 문제은행(`data/question_bank.json`) 시딩 스크립트를 "다 끝나야 저장"하게 짰다가 4번째 학년에서 Bedrock `ServiceUnavailableException`(일시적 과부하, 아마도 동시에 서버 수동 테스트 중이라 겹침)으로 죽으면서 이미 만든 3개 학년 분량이 통째로 날아갔다 — 학년 단위 즉시 저장 + 지수 백오프 재시도로 고쳤다.
- 연습장(그림판) 모달의 "닫기"가 그릴 때마다 무조건 캔버스를 저장하고 "그려짐" 표시를 붙이게 짰더니, 지우기 → 닫기를 해도 표시가 다시 붙는 버그가 났다 — Playwright로 지우기 시나리오까지 직접 재현해서 발견, `padHasContent` 플래그로 "실제로 뭔가 그려졌는지"를 따로 추적하도록 고쳤다.
- 영어 확장 때 채점 도구를 `grade_submission`/`grade_english_submission` 둘로 나누면서 SYSTEM_PROMPT에 "과목별로 다른 채점 도구를 쓰라"고만 적었더니, 과목이 애매한 채점 요청("6×7 정답은 42인데 아이가 42라고 썼어. 채점해줘")에서 에이전트가 학년·난이도를 되묻는 회귀가 생겼다 — 자동 평가 실행기(`run_eval.py`)가 잡아냈다. 채점 도구는 학년·난이도 파라미터가 아예 없는데도 "학습지 생성" 규칙(학년 확인)이 새어 들어간 것 — 프롬프트를 "학습지 생성"/"채점" 섹션으로 명확히 분리하고 "채점 요청엔 학년·난이도가 필요 없다"를 명시해 해결.
- 같은 모델을 지수 백오프로 재시도하는 기존 방식(`invoke_with_retry`)은 "일시적 스로틀링"만 가정했는데, 2026-09-17에 하루 동안 학습지 생성 테스트를 반복하다가 실제로 `ThrottlingException: Too many tokens per day`(계정 일일 토큰 한도 초과)를 만났다 — 같은 모델을 아무리 기다려도 그날은 절대 성공할 수 없는 오류였다. 재시도 대상을 "같은 모델을 기다리기"에서 "다른 모델로 즉시 교체하기"로 바꿔 `MODEL_FALLBACK_CHAIN`(Anthropic 계열 5개 우선 + Nova 계열 4개, `src/tools.py`)을 순서대로 시도하도록 고쳤다 — 모델마다 한도가 별도로 관리되는 것으로 보여 이 방식이 실제로 유효하다.
- id 15(과목 미지정 "아무거나 줘") 회귀를 고치는 1차 시도에서, "과목이 지정되지 않은 경우"라는 조건을 너무 넓게 잡아 "학년만 있고 과목을 아예 언급 안 한" id 2("1학년 학습지 만들어줘")까지 되묻게 만드는 새 회귀를 만들었다(round7, 0/1) — "명시적으로 아직 못 정했다고 말한 경우"(아무거나 줘·상관없어 등)와 "그냥 언급을 안 한 경우"를 같은 조건으로 뭉뚱그린 게 원인이었다. 두 경우를 프롬프트에서 명시적으로 구분해(전자만 되묻고, 후자는 기존대로 수학으로 간주) round8에서 21/21 회귀 없이 해결했다.

**최종 채택한 접근**
- 오류 교차검증은 배포 **전** 완료를 원칙으로 하고(실패 시 자동 교체 → 최대 3회 재시도 → HITL 승인 후 문제은행 대체), "5분 이내" 성공 기준에 검증 시간까지 포함시켰다 — 사후 발견은 예방이 아니라 통계에 불과하다는 판단.
- 채점 정답 인정 범위(단위·띄어쓰기·분수-소수·전각반각)를 정규화 함수 하나로 모아 처리해, 힌트 부분점 로직과 분리했다.

**남은 한계**
- 문제은행(수학·영어 둘 다)은 학년별 '표준' 난이도만 채워져 있다 (쉬움/어려움 미채움 — 그 조합에서 검증이 반복 실패하면 빈 문제은행으로 대체될 수 있음).
- 부모 화면 PIN은 클라이언트 상수(`0000`)라 실제 보안이 아니다 — 같은 기기를 쓰는 아이의 우연한 접근만 막는 수준.
- 주간 리포트는 최근 7일 롤링 집계만 있고, "정말 주 1회"처럼 특정 요일에 강제로 보여주거나 카톡 등으로 알려주는 기능은 없다. 난이도 조정도 서버에 저장되는 게 아니라 이 기기의 `localStorage`에만 남는다 (기기를 바꾸면 초기화됨, 과목 구분 없이 공용).
- 과목 통합 미완료 게이트(`subjectDone`)는 세션 메모리(자정 기준 로컬 초기화)일 뿐 서버 강제가 아니다 — 새로고침해도 사라지진 않지만(자정 전까지는 유지), 서버 재시작이나 다른 기기에서는 추적되지 않는다.
- 모델 폴백 체인은 목(mock)으로 전환 로직 자체를 검증했고(첫 모델 실패 → 다음 모델로 즉시 전환, 재시도 불가능한 오류는 전환 없이 즉시 raise, 체인 전체 소진 시 마지막 오류 raise), 이후 `us.` haiku가 실제로 일일 한도에 걸린 채로 `global.` haiku가 성공하는 것도 라이브로 확인했다 — 같은 모델의 `us.`/`global.` 리전 프로파일도 별도 한도로 관리되는 것으로 보인다. 다만 9개 모델 전부를 라이브로 순회하는 극단적 상황(체인 전체 소진)까지는 확인 못 했다.
- Dockerfile은 작성해 `src.api:app`을 정상 노출하는 구조까지 확인했지만, 이 환경에 Docker 자체가 없어 `docker build`/`docker run` 실행 검증은 못 했다(Python 문법·경로·엔트리포인트만 확인).
- 한문 확장, RAGAS 평가(1차 범위가 RAG를 안 써서 지표 자체가 아직 적용 안 됨)는 이후 단계. (영어 확장·점수(별) 시스템은 2026-09-17에 구현 완료됨)
- 점수(별) 시스템은 누적치가 `stars` 테이블에 추가된 시점부터 새로 쌓인다 — 그 이전에 쌓인 채점 기록(오늘 딴 별 수 계산에는 소급 반영됨)은 누적 별 수에는 반영되지 않는다(마이그레이션 특성상 자연스러운 결과, 실제 사용 시작일부터는 문제없이 누적됨)

## 핵심 코드 위치
(2026-09-17: `agent.py`가 830줄까지 늘어나 단일 책임 원칙을 어긴다는 자체 감사 지적을 반영해 `db.py`·`api.py`로 분리했다 — 아래 세 파일 참고)
- `src/agent.py` — LangGraph 핵심 루프(생성→검증→승인/대체, `subject`로 수학·영어 분기), ReAct 에이전트(`REACT_AGENT`), 과목별 학년범위 가드레일(`SUBJECT_GRADE_RANGE`)만 남김. 모델 폴백(`_build_react_agent`·`_ainvoke_with_retry`, 아래 트라이앤에러 참고)도 여기 있음
- `src/db.py` — SQLite 저장소(`attempts`·`grades`·`stars`·`wrong_answers` 4테이블), 점수(별) 산정·누적(`stars_for_grade`·`log_grade`·`get_stars_summary`), 오답노트(`_record_wrong_answer`·`get_wrong_answers`, 과목별 최대 50개 FIFO), 과목별 주간 리포트 집계(`weekly_report`) — LangGraph·FastAPI 어디에도 의존하지 않는 순수 영속성 계층
- `src/api.py` — FastAPI 앱과 라우트 전부(`POST /query`·`/grade`·`/hint`, `GET /report/weekly`·`/stars`·`/wrong-answers`·`/pending-approvals`, `POST /approve`), 정적 파일 마운트. **실행 엔트리포인트가 `src.agent:app`에서 `src.api:app`으로 바뀌었다** (`run.sh`·`Dockerfile` 갱신 완료, `uvicorn src.api:app`)
- `src/tools.py` — 수학: 문제 생성(`generate_math_problems`)·오류 교차검증(`cross_validate_problem`)·채점(`grade_answer`)·힌트(`generate_hint`). 영어: 문제 생성(`generate_english_problems`)·오류 교차검증(`cross_validate_english_problem`, 오답 3개까지 검증)·채점(`grade_english_answer`)·힌트(`generate_english_hint`). 모델 폴백 체인(`MODEL_FALLBACK_CHAIN`)과 재시도 엔진(`invoke_with_retry`)도 여기 있음
- `src/retriever.py` — RAG 파이프라인 (1차는 수학 자체생성이라 미사용, 확장 단계에서 구현 예정)
